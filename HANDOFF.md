# HANDOFF — состояние проекта и что делать дальше

Дата: 2026-07-28. Версия 0.1.0-alpha.

## Что сделано

Полностью рабочий MCP-сервер для Lamoda Seller Partner API, собранный офлайн из
официальной спецификации.

- `core/` — транспорт JSON-RPC, авторизация с авто-обновлением токена, каталог,
  гейт безопасности, постраничный обход, хранилище кабинетов.
- `lamoda_mcp/endpoints.yaml` — 155 методов: 120 чтение, 33 запись,
  2 необратимых, 12 скрытых служебных.
- `lamoda_mcp/server.py` — 13 тулов на FastMCP, транспорт stdio.
- `lamoda_mcp/safety_overrides.yaml` — ручная курация безопасности, источник истины.
- 53 офлайн-теста, сеть не требуется. Аудит «ноль мутаций в read» проходит.
- Упаковка: `pyproject`, `serve.py` с самоподъёмом окружения, `install.py` на
  4 клиента.

## Главное ограничение

**Ни один запрос не выполнялся на живом кабинете Lamoda.** Кредов не было.

Что это значит практически:

| Слой | Статус |
|---|---|
| Перечень методов, пути, имена | факт из официальной спеки |
| Контракт авторизации | факт из официальной спеки |
| Поведение «ошибка приходит с HTTP 200» | факт из схем ответов |
| Формы `params` | вывод из схем, не подтверждено |
| `items_path`, пагинация | вывод из схем, не подтверждено |
| Разметка read/write/destructive | ручная курация по описаниям |

Урок marketplace-mcp, из-за которого это выделено отдельно: схема WB обещала
массив по пути `result.items`, живой ответ отдавал `data.listGoods`, обход
страниц молча возвращал ноль строк, и обнаружилось это только живым прогоном.

## Первый шаг, когда появятся креды

Порядок именно такой — от дешёвого к дорогому.

```bash
cd lamoda-mcp-ru
export LAMODA_CLIENT_ID=...
export LAMODA_CLIENT_SECRET=...

# 1. Токен вообще выдаётся? Какие права у ключа?
python3 -c "
import asyncio, sys; sys.path.insert(0,'.')
from lamoda_mcp.server import lamoda_check_auth
print(asyncio.run(lamoda_check_auth()))
"

# 2. Один безопасный чтение-метод, посмотреть форму ответа живьём
python3 -c "
import asyncio, sys, json; sys.path.insert(0,'.')
from lamoda_mcp.server import lamoda_call_method
print(asyncio.run(lamoda_call_method('v1.orders.list', {'limit': 1, 'page': 1})))
"

# 3. Широкий свип по чтению + починка items_path по фактическим ответам
python3 scripts/validate_items_path.py --delay 0.5          # сначала отчёт
python3 scripts/validate_items_path.py --delay 0.5 --fix    # затем правки

# 4. Перепроверить инварианты
python3 scripts/audit_safety.py && python3 -m pytest -q
```

**Запускать локально, не в песочнице агента.** В marketplace-mcp широкий live-свип
не уложился в лимит времени bash и упёрся в rate limit — каждый ответ 429 съедал
секунды под ожиданием.

## Что проверить в первую очередь

Отсортировано по вероятности, что там окажется расхождение.

1. **Формат заголовка авторизации.** Сейчас `Authorization: Bearer <token>` —
   выведено из `tokenType: "bearer"` в спеке. Если Lamoda ждёт токен без слова
   `Bearer` (как это оказалось у WB), правится в одном месте:
   `core/client.py`, сборка `headers` в методе `call`.

2. **Время жизни токена.** Документация Lamoda говорит 15 минут, пример в спеке
   показывает `expiresIn: 86400`. Сейчас значение берётся из ответа, дефолт при
   отсутствии — 900 секунд. Посмотрите, что придёт реально.

3. **23 серьёзных расхождения спеки** (поле `spec_conflict` в каталоге). Самое
   тревожное: `/v1/nomenclature.validate-price` с `method` = `set-price`.
   Проверять **только через `dry_run`**, пока не станет ясно, что это.

4. **14 постраничных методов без `items_path`** (список
   `items_path_unresolved` в каталоге). Обход по ним работает через запасные
   пути и предупреждает, но точное значение закроет `validate_items_path.py`.

5. **Права ключа.** У WB и Ozon часть разделов закрывалась 401/403 по scope.
   `lamoda_check_auth` показывает выданный `scope` — сверьте с разделами каталога.

## Не сделано намеренно

- **B2B Platform API** (`api-b2b.lamoda.ru`, REST: заказы, отгрузки, ярлыки,
  вебхуки). Публичной машиночитаемой спеки нет — проверено: `/openapi.json`,
  `/swagger.json`, `/api/docs`, `/swagger/doc.json` и ещё четыре пути отвечают
  404, `/health` отвечает 401. Строить каталог по тексту документации — это
  гипотеза поверх гипотезы; отложено сознательно.
- **Unified Seller Partner API v2 (REST)** — по той же причине. Несколько
  `/v2/*` путей уже есть внутри v1-спеки, они помечены полем `api_version`.
- **Публикация на PyPI** — пакет ставится из git.
- **GitHub-репозиторий не создан и не запушен.** Локальный git инициализирован,
  коммит есть. Это шаг человека.
